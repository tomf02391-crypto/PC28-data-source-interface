## 四、Python 项目接入（GitHub Actions 脚本 / 后端）

```python
import json
import urllib.request

URL = "https://cdn.jsdelivr.net/gh/tomf02391-crypto/PC28-data-source-interface@main/data_pc28.json"

def get_latest():
    """获取最新一期 PC28 开奖数据，返回 dict 或 None"""
    try:
        with urllib.request.urlopen(URL, timeout=15) as resp:
            d = json.loads(resp.read().decode("utf-8"))
        items = d.get("data") or []
        if items:
            return items[0]
    except Exception as e:
        print(f"[PC28] 获取失败: {e}")
    return None

# 使用示例
if __name__ == "__main__":
    item = get_latest()
    if item:
        print(f"期号: {item['nbr']}")
        print(f"号码: {item['number']}  和值: {item['num']}  形态: {item['combination']}")
        print(f"开奖时间: {item['date']} {item['time']}")
    else:
        print("未获取到数据")
```

## 七、常见问题

### 1. jsDelivr 缓存延迟
jsDelivr 有 CDN 缓存，数据更新可能有几分钟延迟。对实时性要求高时：
- 使用备用源 raw.githubusercontent.com（无缓存，但国内访问慢）
- 或者在 URL 后加版本号强制刷新：`@main` 后追加 `?t=时间戳`

### 2. 自动刷新频率
数据每 3 分钟更新一期，前端建议每 3 分钟轮询一次；后端脚本建议 3-5 分钟跑一次。

### 3. 数据为空 / 请求失败
- 先确认仓库 Actions 是否正常运行（可访问仓库 Actions 页面查看）
- 检查网络能否访问 jsDelivr（国内一般可以）
- 降级到备用源重试
