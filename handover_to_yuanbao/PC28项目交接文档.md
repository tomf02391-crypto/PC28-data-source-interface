## 一、项目概况

PC28 开奖自动推送系统，每 3 分钟抓取最新开奖数据，渲染高清图片（3616×1216）并推送到 Telegram 频道。

| 项目 | 说明 |
|------|------|
| 数据源仓库 | `tomf02391-crypto/PC28-data-source-interface` |
| 主脚本 | `fetch_and_push_hd.py`（v4 高清版，370 行） |
| Telegram 频道 | `@pc28jndkj`（图片推送） |
| 群组推送 | 文字消息推送（通过 GROUP_ID 配置） |
| 触发机制 | GitHub Actions（`fetch-pc28.yml`，`*/3 * * * *`） + CF Worker（`pc28trigger`，`*/3 * * * *`）互补触发 |

## 四、脚本核心逻辑（fetch_and_push_hd.py）

### 4.1 数据源（双源容错）

| 源 | 地址 | 说明 |
|----|------|------|
| 主源 | `pc28.help` → `https://pc28.help/api/kj.json?t=时间戳` | 无密钥，通用 |
| 备用源 | `yu28.top` → `https://yu28.top/api/kj.json?t=时间戳` | 需 `YU28_API_KEY` 环境变量 |

配置方式：环境变量 `YU28_API_KEY`。有则双源，无则只用主源。主源失败自动切备用。

### 4.2 数据校验

- 期号：5 位以上纯数字
- 号码：格式 `x+y+z`，三个数字
- 和值校验：自动计算三个球的和，与接口返回的 `num` 字段比对
- 组合校验：自动计算 `大/小` + `单/双`，与 `combination` 字段比对
- 时间校验：开奖时间与当前时间偏差超过 20 分钟则视为异常，拒绝推送
- 形态识别：自动判断豹子 / 对子 / 顺子 / 杂六

### 4.3 图片渲染（v4 高清版，3616×1216）

- **底图**：用户原图（冬/夏两套），满分辨率 3616×1216
- **时令判断**：以纽约时区夏令时为准（4~10 月为夏时令，用夏底图；其余为冬时令，用冬底图）
- **期号渲染**：8 位数字从 `chars_hd/` 中取字符，按 SLOT_X 坐标定位，重新着色（冬=红色，夏=橙金色）
- **球数字渲染**：4 个球位置（前三球+和值），字符从 `chars_hd/` 取，着色（冬=黑色，夏=球1/2=黑色、球3/4=金色）
- **字符缺失降级**：自动生成 208px 粗体字作为 fallback

### 4.4 去重机制

```
last_sent.txt 记录上次推送的期号
→ 新期号 <= 已推送期号时跳过推送（仅更新 data_pc28.json）
```

### 4.5 Telegram 推送

| 推送目标 | 类型 | 配置 |
|----------|------|------|
| 频道 `@pc28jndkj` | 图片（带 caption） | `TG_BOT_TOKEN` + `CHANNEL_ID` |
| 群组（可选） | 文字消息 | `TG_BOT_TOKEN` + `GROUP_ID` |

### 4.6 Git 自动提交

推送成功后自动：
1. `git add data_pc28.json last_sent.txt`
2. `git commit -m "Update data ..."`
3. `git push origin main`

## 六、触发机制（互补模式）

### 6.1 GitHub Actions

- 配置文件：`.github/workflows/fetch-pc28.yml`
- 定时：`*/3 * * * *`（每 3 分钟）
- 手动触发：支持 `workflow_dispatch`

### 6.2 Cloudflare Worker

- Worker 名称：`pc28-trigger`
- 定时：`*/3 * * * *`
- 功能：通过 GitHub API 触发 `fetch-pc28.yml` workflow
- 脚本：`pc28_api_worker.js`（91 行，兼容版）
- 环境变量：`GH_TOKEN`（Secret）、`GH_REPO`、`GH_WORKFLOW`

### 6.3 互补策略

两个触发独立运行，任一触发成功即可。任意一个挂掉，另一个仍能保证推送。
